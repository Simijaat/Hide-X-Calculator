Update: Implemented Photos App in Vault
- Added `PhotosScreen` using Jetpack Compose with a 3-column grid layout as requested ("grid view Wagrah ki trah 2-3 style me photo dikhani hai").
- Implemented `PhotosViewModel` to manage photo states, import, export, and delete logic.
- Integrated Android's `PhotoPicker` for adding new photos seamlessly.
- Used `VaultStorageManager` to securely save, load, delete, and list photos via Storage Access Framework (SAF) `.nomedia` hidden subfolder.
- Used `VaultSecurityManager` alongside `VaultCryptoManager` to encrypt and decrypt the bytes of imported photos using the session's active master key to ensure robust privacy.
- Included an internal full-screen photo viewer directly within the vault context.
- Added 'Export' (Unhide) functionality to push photos back out.
- Added 'Permanent Delete' functionality that permanently purges photos bypassing any recycle bin ("hamesha hamesha ke liye delete").
- Wired up `VaultCalcNavigation.kt` to route the Vault's "Photos" icon to the newly built system, overriding the previous placeholder.

Update: Fixed Photo loading and importing logic
- Added `loadThumbnail` and `loadFullImage` to `PhotosViewModel` to compute optimal `inSampleSize` when decoding photos to prevent UI freezes and OOM (Out of Memory) crashes on large images.
- Replaced direct byte array decodes in `PhotosScreen.kt` with `loadThumbnail` in the grid and `loadFullImage` in the viewer.
- Updated `VaultStorageManager` to open file streams with `"w"` instead of `"wt"` to prevent potential binary corruption on certain devices.
- Switched `PickMultipleVisualMedia` to `GetMultipleContents` in `PhotosScreen.kt` to allow source URI modifications.
- Implemented logic in `importPhotos` to delete the original source photo (hiding it from gallery) via `DocumentsContract.deleteDocument` and `contentResolver.delete` upon successful Vault import.

Update: Improved Photo Deletion & Fixed UI Rendering
- Fixed a bug in `PhotoViewerOverlay` where `loadThumbnail` was erroneously used instead of `loadFullImage`, which resulted in a blurry full-screen image viewing experience.
- Resolved potential binary file corruption upon saving new configurations by ensuring `VaultStorageManager` strictly uses the `"wt"` (write & truncate) parameter for output streams.
- Refactored `importPhotos` in `PhotosViewModel` to aggressively target and delete the original source image (to properly 'hide' it). It parses the source URI through `MediaStore` to resolve the actual file path and performs a direct file deletion (leveraging the application's `MANAGE_EXTERNAL_STORAGE` permission), whilst falling back to `ContentResolver.delete` when necessary.

Update: Prevent Vault lock on external intents
- Addressed issue where the Calculator app locked the Vault upon opening external applications like the Photo Picker and Document Exporter due to interpreting this behavior as a standard `onPause` app exit.
- Introduced a Boolean `isExpectingExternalActivity` to `VaultSecurityManager` to whitelist controlled lifecycle events.
- Updated `PhotosScreen` and `PhotosViewModel` to activate this flag prior to launching `photoPickerLauncher` or `exportLauncher`.
- Refactored `MainActivity`'s `onResume` and `onPause` to intercept lifecycle changes and bypass the standard 1-second loading screen + Vault lock if the transition was explicitly expected.
