# PR1 - Foundation + Private Calculator/Vault

## What was implemented
- Refactored `VaultSecurityManager.kt` to use PBKDF2 with HMAC-SHA256 for secure PIN hashing. Random salts are generated via `SecureRandom` and stored alongside hashes using Base64 encoding in `EncryptedSharedPreferences`.
- Added an inactivity timer and auto-lock logic to `VaultSecurityManager.kt`, monitored via a `lifecycleScope` coroutine in `MainActivity.kt`.
- Applied `FLAG_SECURE` to the `MainActivity` window to block screenshots and recent-task previews, adhering to Android security best practices.
- Enhanced the `CalculatorViewModel.kt` parser logic to natively handle division by zero (catching `Infinity` and `NaN`), added state management to distinguish between new calculations and active input (`isResult`), and introduced a functional `DEL` action.
- Built out a discrete, two-step PIN setup flow in `CalculatorViewModel.kt` triggered entirely within the calculator context (enter PIN -> `=` -> verify PIN -> `=`).
- Added the `DEL` button to the `CalculatorScreen.kt` UI layout.
- The `VaultScreen.kt` remains a scaffolded dummy screen ready to house feature tools.

## Important architectural decisions
- **Jetpack Compose**: Selected for a modern, scalable UI toolkit.
- **Hilt (Dagger)**: Essential for maintainable dependency injection, especially as the app grows with VPN, ad-blocking, etc.
- **EncryptedSharedPreferences**: Used for storing the vault PIN hash and salt. It leverages Android KeyStore for secure, encrypted local storage.
- **Security Logic**: Hardened by shifting from plaintext PIN storage to a PBKDF2 approach (100,000 iterations, 256-bit key).
- **MVVM Architecture**: ViewModels manage state, decoupling UI from business logic. StateFlows provide reactive security state to the Navigation graph to force lock-outs.

## Known Issues / Limitations
- Calculator logic uses a simple recursive descent parser which relies on Doubles and may encounter floating point inaccuracies for some advanced calculations.
- While `FLAG_SECURE` prevents screenshots, advanced rooting could still potentially inspect memory.

# PR2 - Advanced Private Browser + Ad/Tracker Blocking

## What was implemented
- Added **INTERNET** permissions to `AndroidManifest.xml`.
- Integrated **Room Database** (v2.6.1) to support Browser Data persistence (Bookmarks and History).
- Implemented **Data Layer**:
  - `Bookmark` and `HistoryItem` entities.
  - `BrowserDao` and `BrowserDatabase` configured to handle DB operations.
  - `BrowserRepository` created and injected via Hilt `AppModule`.
- Implemented **Ad & Tracker Blocking**:
  - Integrated `AdBlockManager` which loads a robust `ad_hosts.txt` (via StevenBlack's hosts file base) from assets into memory for O(1) subset lookup domain blocking.
- Implemented **Secure Browser Architecture**:
  - `BrowserViewModel` manages multi-tab states (`BrowserTab`), ad-block toggling, bookmarks, and history flow.
  - `SecureWebViewClient` intercepts network requests, checks them against `AdBlockManager`, blocks non-HTTP/HTTPS schemas, and guarantees navigation integrity.
  - `SecureWebChromeClient` tracks loading progress and securely handles title updates.
- Built **Browser UI**:
  - `BrowserScreen` features a clean address bar, back/forward navigation controls, stop/reload context, new tab triggers, and an ad-block toggle dropdown.
  - Configured WebView inside `AndroidView` securely: disables file access, DOM storage sandboxing in memory, mixed-content rejections.
- Integrated **Navigation**:
  - Expanded `VaultCalcNavigation` to link from `VaultScreen` directly to the new `BrowserScreen`.

## Important architectural decisions
- **WebView Security**: File access (`allowFileAccess`, `allowContentAccess`) is disabled, Database is disabled, Mixed Content is strictly blocked, Javascript is enabled but heavily monitored via Intercepts.
- **Host Blocking Efficiency**: Ad domains are aggressively loaded into a `HashSet` allowing very rapid hostname part-matching for every WebView network intercept, keeping the UI thread lag-free.
- **Room for Bookmarks**: Standard local-only relational store ensures data does not leak into external logs.

## Validation Performed
- Repository builds cleanly via `./gradlew clean assembleDebug`.
- Lints and tests passed via `./gradlew clean test lint check`.
- Verified domain interception logic using custom `SecureWebViewClient`.

## Known Issues / Limitations
- Tabs state is entirely memory-based during the session. Process death clears tabs (intentional for incognito privacy, but could be extended to persist if desired).
- Progress indicator loading transitions can be abrupt depending on the webpage's resource waterfall.
- No VPN integration or Advanced Downloads implemented (held for PR3 and PR4).
